# SplitLane

[English](README.md)

SplitLane — приложение для Windows, которое делит трафик по программам. Программы раскладываются по двум дорожкам, «Через VPN» и «Напрямую»: программы дорожки VPN выходят в сеть через ваш VPN, остальные — напрямую, через обычное подключение. VPN — это exit node Tailscale или сервер из ключа (ссылки), подписки или файла WireGuard. Приложение для тех, кто хочет пускать через VPN только часть программ, например потому что некоторые сайты через VPN работают медленно или не работают вовсе. Программы переносятся с дорожки на дорожку перетаскиванием.

Это бета-версия.

## Как это устроено

- Окно SplitLane работает без прав администратора. Оно отправляет команды службе SplitLane — фоновому служебному процессу с правами администратора, который запускает планировщик задач при входе в Windows.
- Служба запускает ядро, которое поставляется вместе с SplitLane (sing-box 1.14.4 без изменений). Ядро перехватывает трафик через виртуальный адаптер и отправляет каждое соединение на дорожку по пути программы, которая его открыла.
- С Tailscale дорожка VPN идёт через встроенный узел Tailscale внутри ядра. Это отдельное устройство в вашей сети Tailscale с именем `<имя ПК>-splitlane`; оно выходит через выбранный вами exit node. С ключом, подпиской или файлом WireGuard ядро само подключается к выбранному серверу, без узла Tailscale. Дорожка «Напрямую» идёт через обычное подключение.
- Одна из дорожек — основная. По ней идут программы, которые вы не закрепили; закреплённые остаются на своей дорожке.
- Если приложение Tailscale для Windows установлено и использует exit node, SplitLane выключает этот exit node, пока деление включено, и включает его обратно, когда вы выключаете деление. После сбоя или перезагрузки Windows он включает его обратно при следующем запуске службы.

## Что нужно

- Windows 10 или 11, x64.
- VPN: учётная запись Tailscale (сеть Tailscale) с exit node, которым вам можно пользоваться, или сервер протокола, который поддерживает SplitLane (см. [«Ключи, подписки и WireGuard»](#ключи-подписки-и-wireguard)). VPN должен выходить в интернет не с того адреса, что этот компьютер.
- Приложение Tailscale для Windows не обязательно: если оно установлено и использует exit node, SplitLane выключает этот exit node, пока деление включено, и затем включает его обратно.
- Учётная запись Windows с правами администратора. SplitLane устанавливают и используют под одной и той же учётной записью: если подтвердить запрос Windows (UAC) другой учётной записью, установка остановится.

## Установка

1. Скачайте `SplitLane-Setup-<версия>.exe` и `SplitLane-Setup-<версия>.exe.sha256` со страницы [выпусков (Releases)](https://github.com/splitlane-app/splitlane/releases).
2. Проверьте загрузку. В PowerShell, в папке с обоими файлами (подставьте версию вместо `<версия>`):

   ```powershell
   $file = 'SplitLane-Setup-<версия>.exe'
   $expected = (-split (Get-Content "$file.sha256" -Raw))[0]
   (Get-FileHash $file -Algorithm SHA256).Hash -eq $expected
   ```

   `True` значит, что файл совпадает с контрольной суммой выпуска.
3. Запустите установщик. Он пока не подписан, поэтому SmartScreen показывает «Система Windows защитила ваш компьютер»: нажмите «Подробнее», затем «Выполнить в любом случае».
4. Установщик один раз просит права администратора, ставит SplitLane для всех пользователей в `%ProgramFiles%\SplitLane` (каталог не выбирается) и настраивает службу для пользователя, который вошёл в Windows. На последней странице — галочка «Запустить SplitLane».

Установщик говорит по-русски или по-английски, как Windows.

Установка поверх прежней версии идёт так же: установщик сначала останавливает службу прежней версии и включает обратно exit node приложения Tailscale, если он был выбран. Настройки и вход в Tailscale остаются. Тихая установка: `SplitLane-Setup-<версия>.exe /S` (окно не запускается; ненулевой код выхода означает, что установка не удалась).

winget: скоро.

## Первый запуск

1. Если окно показывает «Первая настройка», нажмите «Установить службу» и подтвердите запрос Windows. Обычно это уже сделал установщик, так что этот экран появляется, только когда службу нужно починить.
2. На экране «Подключите VPN» выберите способ подключения: «Tailscale», «Ключ или подписка» или «Файл настроек». Для ключа, подписки или файла WireGuard см. [«Ключи, подписки и WireGuard»](#ключи-подписки-и-wireguard). Для Tailscale нажмите «Войти в Tailscale». Окно SplitLane откроет страницу входа в браузере: войдите в ту сеть Tailscale, где есть ваш exit node. Так выполняется вход встроенного узла SplitLane — нового устройства `<имя ПК>-splitlane`; приложение Tailscale для этого не нужно. Если в вашей сети устройства нужно одобрять, одобрите его в консоли администратора Tailscale; окно продолжит само.
3. Выберите exit node или сервер и нажмите «Включить деление».
4. Разложите программы по дорожкам. Карточку можно перетащить с одной дорожки на другую, файл `.exe` или ярлык — из Проводника на дорожку, а кнопка «+ Добавить» предлагает программы, которые сейчас в сети, установленные программы и выбор файла. Те же действия есть в контекстном меню карточки («Пустить через VPN», «Пустить напрямую», «Открепить») и доступны с клавиатуры.

Закреплённая программа остаётся на своей дорожке, остальные идут по основной («сделать основной» у другой дорожки меняет её). По умолчанию программа — это вся её папка, чтобы обновлялки и вспомогательные процессы шли той же дорожкой; это меняется в карточке программы. Кнопка «Настройки и подключение» в шапке (или «Настройки…» в меню значка) открывает экран «Подключение»: exit node, выход из Tailscale, язык и настройки «Запускать при входе в Windows», «Включать деление при запуске», «Проверять обновления» и «Показывать уведомления».

Закрытое окно остаётся значком в области уведомлений; пока оно там, SplitLane показывает уведомление Windows, когда деление остановилось с ошибкой, нет связи с VPN-сервером, приложение Tailscale снова включило exit node, истёк вход в Tailscale или вышла новая версия. «Выход» в меню значка выключает деление и останавливает службу.

## Ключи, подписки и WireGuard

Вместо exit node Tailscale дорожка VPN может идти через VPN-сервер — свой или VPN-сервиса. Ядро SplitLane само умеет эти протоколы:

- **Протоколы:** VLESS (в том числе Reality и `xtls-rprx-vision`), VMess, Trojan, Shadowsocks (в том числе Shadowsocks 2022 и ключи Outline), Hysteria2 и TUIC v5 — по ссылкам (`vless://`, `vmess://`, `trojan://`, `ss://`, `hysteria2://` или `hy2://`, `tuic://`); WireGuard — по файлу `.conf`.
- **Транспорты:** без транспорта (TCP), WebSocket, gRPC, HTTPUpgrade, HTTP/2 и QUIC; TLS с SNI, ALPN и отпечатком uTLS или Reality.
- **Подписки:** адрес `https://`, по которому отдаётся список ссылок — простым текстом или в base64.

**Как добавить серверы.** На экране «Подключите VPN» (или позже на «Подключение») выберите «Ключ или подписка», вставьте одну или несколько ссылок (по одной в строке) или один адрес подписки и нажмите «Добавить». Для WireGuard выберите «Файл настроек» и укажите файл `.conf`; его текст можно и вставить в «Ключ или подписка». SplitLane покажет, сколько серверов добавлено и какие строки отклонены и почему, с номером строки (саму строку он не показывает: в ней ключ). Ссылка с тем, что SplitLane не поддерживает, отклоняется с причиной, а не понимается наполовину.

**Выбор сервера.** Серверы показаны списком с именем, протоколом и источником (вручную, файл или имя подписки). Выбранный сервер ведёт дорожку VPN, а шапка показывает его как «<сервер> · <протокол>». Смена сервера при включённом делении ненадолго перезапускает деление, как смена exit node. Выбор exit node возвращает дорожку VPN к Tailscale.

**Подписки.** На экране «Подключение» у каждой подписки видно число серверов, время последнего обновления и ошибку последнего обновления, если оно не удалось. «Обновить» скачивает подписку заново и заменяет её серверы; выбранный сервер остаётся выбранным, если он есть в подписке. «Удалить» удаляет сервер или подписку со всеми её серверами. Пока деление включено, выбранный сервер нельзя удалить, а его подписку — обновить или удалить.

Ссылки, файлы WireGuard и адреса подписок — секреты. SplitLane хранит их только в `%ProgramData%\SplitLane\servers.json` (только администраторы); в журналы и архивы диагностики они не попадают.

**Свой сервер.** В [scripts/server](scripts/server/README.ru.md) есть скрипт, который ставит на VPS с Debian или Ubuntu VLESS + Reality, Hysteria2, Shadowsocks 2022 и WireGuard и выводит ссылки, файл `.conf` и, по желанию, адрес подписки.

**Ограничения.**

- Только перечисленные выше протоколы и транспорты. AmneziaWG и OpenVPN пока не поддерживаются. Транспорты `xhttp`, `splithttp` и `kcp`, заголовок `http` для TCP, плагины Shadowsocks и подписки в форматах Clash и sing-box отклоняются с причиной.
- Подписки обновляются только по кнопке «Обновить», не по расписанию.
- Сервер без UDP не пропустит UDP-трафик программ дорожки VPN (игры, звонки).
- Нет проверки задержки и автоматического выбора сервера; дорожку VPN ведёт один сервер.

## Обновления

SplitLane проверяет последний выпуск на [GitHub Releases](https://github.com/splitlane-app/splitlane/releases) через 30 секунд после запуска окна и затем раз в 24 часа, пока окно работает, если включена настройка «Проверять обновления» (по умолчанию включена). Проверить можно и в любой момент: «Проверить обновления» в меню значка или на экране «Подключение».

Когда выходит новая версия, плашка предлагает «Обновить». SplitLane скачивает установщик, сверяет его SHA-256 с файлом `.sha256` того же выпуска и запускает установщик тихо; Windows просит подтверждение. Установщик останавливает службу, включает обратно exit node приложения Tailscale, если он был выбран, ставит новую версию и снова запускает окно. Деление остаётся включённым или выключенным, как было. Затем окно показывает «SplitLane обновлён до X» или причину, по которой обновление не установилось.

Сверка SHA-256 подтверждает, что файл скачан целым, но не то, кто его сделал: установщик пока не подписан.

## Удаление

«Параметры» → «Приложения» → SplitLane → «Удалить», или `%ProgramFiles%\SplitLane\Uninstall SplitLane.exe`. Перед удалением деинсталлятор выключает деление и, если приложение Tailscale использовало exit node, включает его обратно.

Галочка «Удалить настройки и вход в Tailscale» (по умолчанию выключена) удаляет ещё `%ProgramData%\SplitLane` и ваш `%AppData%\SplitLane`. Без неё они остаются для следующей установки.

В обоих случаях устройство `<имя ПК>-splitlane` остаётся в вашей сети Tailscale. Удалите его в [консоли администратора Tailscale](https://login.tailscale.com/admin/machines).

Тихое удаление: `"%ProgramFiles%\SplitLane\Uninstall SplitLane.exe" /S` — данные остаются, с `/S /PURGE` — удаляются. Деинсталлятор NSIS копирует себя во временную папку и сразу возвращает управление; удаление заканчивается через несколько секунд, когда исчезает папка `%ProgramFiles%\SplitLane`.

## Конфиденциальность

У SplitLane нет телеметрии и собственных учётных записей. Коротко:

- Окно проверяет обновления на GitHub. Автоматическую проверку можно выключить.
- С Tailscale встроенный узел Tailscale обращается к серверам Tailscale, как любое устройство Tailscale. С ключом или файлом WireGuard ядро подключается к этому серверу; подписку служба скачивает с указанного вами адреса, когда вы её добавляете или обновляете.
- Пока деление включено, служба проверяет обе дорожки через `api.ipify.org`, а имена сайтов разрешаются через шифрованный DNS `1.1.1.1` по дорожке VPN.
- Настройки и журналы остаются на компьютере. Архив диагностики покидает его, только если вы сами им поделитесь.

Подробности и как удалить всё: [PRIVACY.md](PRIVACY.md#русский).

## Известные ограничения беты

- Установщик и программы не подписаны. SmartScreen предупреждает о скачанном установщике, а проверка обновлений подтверждает целостность, но не подлинность.
- Один пользователь Windows на компьютер. Деление действует на весь компьютер: программы в других сеансах Windows идут по тем же дорожкам, но управлять SplitLane может только пользователь, который его установил.
- У ключей, подписок и файлов WireGuard свои ограничения: см. [«Ключи, подписки и WireGuard»](#ключи-подписки-и-wireguard).
- Установка только в `%ProgramFiles%\SplitLane`.
- Встроенный узел — отдельное устройство в сети Tailscale со своим сроком действия входа. Когда он истекает, SplitLane просит войти снова.
- DNS общий для обеих дорожек. Пока дорожка VPN работает, имена разрешаются через неё, поэтому сети раздачи контента могут выдавать программам прямой дорожки серверы рядом с VPN-сервером. Когда VPN-сервер недоступен или включён режим «Всё напрямую», все имена уходят в DNS провайдера.
- Если приложение Tailscale управляет DNS (так по умолчанию), имена MagicDNS не разрешаются, пока деление включено, а если сеть Tailscale переопределяет DNS для всех имён, деление не включается. Проверено только с выключенным управлением DNS в приложении Tailscale.
- Трафик WSL и виртуальных машин идёт по основной дорожке. Так же идут соединения, для которых ядро не определило программу (например, `ping`).
- Программы, которые выходят в сеть через общие системные процессы (например, встроенный веб-компонент Edge), нельзя отделить друг от друга.
- Трафик к частным, локальным адресам и адресам сети Tailscale всегда идёт напрямую.
- IPv6 в интернет не работает, пока деление включено.
- Нет блокировки на случай сбоя. Если ядро упало, трафик идёт напрямую, пока SplitLane не включит обратно exit node в приложении Tailscale (порядка секунды), а затем через этот exit node, пока ядро не перезапустится. Когда SplitLane сам перезапускает ядро (после смены сети, при смене exit node или сервера), трафик на это время идёт через exit node приложения Tailscale. Если приложение Tailscale не установлено или exit node в нём не был выбран, в обоих случаях трафик идёт напрямую.
- Exit node или сервер, который выходит в интернет с того же адреса, что и этот компьютер, не подходит.
- Если в приложении Tailscale был включён автоматический выбор exit node, после выключения деления там будет выбран конкретный узел.
- Если приложение Tailscale установлено, одну его настройку SplitLane читает отладочной командой, формат которой может измениться. После обновления Tailscale один раз включите и выключите деление.
- Сообщения службы (её журнал, причины, по которым установщик останавливается) — на английском в обоих языках.

## Сборка из исходного кода

Нужны Windows 10/11 x64 с Windows PowerShell 5.1, Go 1.27.4 (в `%LOCALAPPDATA%\Programs\go\bin`, иначе из `PATH`), Node.js 24 и pnpm 12.9.1.

1. Получите ядро. sing-box 1.14.4 в git не хранится: скрипт скачивает официальный архив и сверяет SHA-256 со значениями из `scripts/core.sha256`. Итог: `.cache\core\sing-box-1.14.4-windows-amd64\sing-box.exe`.

   ```powershell
   powershell -ExecutionPolicy Bypass -File scripts\fetch-core.ps1
   ```

2. Соберите установщик:

   ```powershell
   powershell -NoProfile -ExecutionPolicy Bypass -File scripts\build-installer.ps1
   ```

   Шаги: `scripts\build-helper.ps1` (служба, в `dist\helper`), затем в `app`: `pnpm install --frozen-lockfile`, двоичный файл Electron, проверка типов, тесты, сборка окна и `electron-builder --win nsis`. Итог: `app\release\SplitLane-Setup-<версия>.exe` и рядом `SplitLane-Setup-<версия>.exe.sha256` (одна строка: `<sha256>  SplitLane-Setup-<версия>.exe`). Последняя строка вывода — `BUILD-OK <путь установщика>`. Версия — `version` в `app/package.json`, её же получает служба. Установщик не подписан.

Сборка с другой версией (три числа `x.y.z`), например для проверки обновлений:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\build-installer.ps1 -Version 0.3.90
```

Эту версию получают служба (`scripts\build-helper.ps1 -Version <x.y.z>`, его можно запустить и отдельно), окно, `SplitLane.exe` и установщик с его именем и `.sha256`; `app/package.json` не меняется.

## Разработка

- **Состав.** `helper/` — служба `splitlane-helper.exe` (Go), единственная часть с правами администратора. `helper/cmd/slctl` — тестовый клиент канала службы. `helper/cmd/slguard` — сторож для проверок на ПК во время разработки; в поставку не входит. `app/` — окно (Electron, React, TypeScript); `app/build/installer.nsh` — дополнения установщика. `scripts/` — получение ядра, сборка и проверка установщика; `scripts/server` — набор для сервера на VPS (скрипт bash, в поставку не входит). `docs/` — спецификации и планы. `.github/workflows/build.yml` — сборка на GitHub Actions.
- **Только служба** (Go 1.27.4, CGO не нужен):

  ```powershell
  cd helper
  $env:CGO_ENABLED = '0'
  go test ./...
  go build -ldflags "-H=windowsgui" -o bin\splitlane-helper.exe .\cmd\splitlane-helper
  go build -o bin\slctl.exe .\cmd\slctl
  go build -o bin\slguard.exe .\cmd\slguard
  ```

  Проверка конфигов настоящим ядром (ядро только читает конфиг): переменная `SPLITLANE_CORE` с полным путём `sing-box.exe` перед `go test ./...`.
- **Окно без установщика.** `powershell -NoProfile -ExecutionPolicy Bypass -File scripts\build-app.ps1` собирает `app\release\win-unpacked\SplitLane.exe`, шесть файлов службы лежат в `helper\` рядом с ним, как их раскладывает установщик (последняя строка `BUILD-OK app\release\win-unpacked`). Это только для разработки: служба работает только из `%ProgramFiles%\SplitLane\helper`, а окно не из `%ProgramFiles%\SplitLane` на экране «Первая настройка» говорит, что SplitLane нужно установить установщиком.
- **Режим разработки.** Служба, собранная из исходного кода, вне места установки запускается только с `--dev`, из процесса с правами администратора, с абсолютными путями:

  ```text
  splitlane-helper.exe --dev --data-dir <репозиторий>\.dev\data --core <репозиторий>\.cache\core\sing-box-1.14.4-windows-amd64\sing-box.exe
  ```

  Каталог `.dev\` в git не попадает. В режиме разработки служба не проверяет, какая программа подключилась к её каналу, поэтому с ней работают `slctl` и сценарная проверка `node scripts/scenario.mjs`.
- **Источник обновлений для проверок.** `SPLITLANE_UPDATE_FEED=http://127.0.0.1:<порт>` — окно берёт выпуски с локального сервера вместо GitHub.
- **GitHub Actions.** `.github/workflows/build.yml` запускается на каждую отправку в любую ветку, на pull request, на метку `v*` и вручную (Actions → build → Run workflow), на `windows-latest`: ядро со сверкой SHA-256, `go vet` и `go test` службы, `scripts\build-installer.ps1`, затем `scripts\test-installer.ps1` и артефакт `SplitLane-Setup-<версия>` (установщик и `.sha256`, хранится 2 дня, на pull request не создаётся). При сбое — небольшой артефакт `test-installer-logs`. В сводке запуска — SHA-256 установщика и итог проверки. На метке `v<версия>` (должна совпадать с `version` в `app/package.json`) задача `release` создаёт черновик выпуска «SplitLane <версия>» с установщиком и `.sha256`. Скачать артефакт: `gh run download <id запуска> -n SplitLane-Setup-<версия>`.
- **Проверка установщика.** `scripts\test-installer.ps1 -Installer <путь>` тихо ставит, ставит повторно и удаляет SplitLane и проверяет файлы, задачу, список доступа папки данных, предохранители Electron и файл итога `%ProgramData%\SplitLane\export\last-install.txt`. Последняя строка — `TEST-OK`, `TEST-FAIL <шаг>: <что>` или `TEST-REFUSED: <причина>`. Скрипт меняет систему и предназначен для бегуна GitHub Actions: на ПК, где уже есть SplitLane или Tailscale, он отказывает, ничего не меняя.
