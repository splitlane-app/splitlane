# Набор SplitLane для сервера

[English](README.md)

`install-singbox-server.sh` превращает Linux VPS в VPN-сервер для подключений SplitLane «Ключ или подписка» и «Файл настроек». Это помощник для проверки SplitLane и для своего сервера; в приложение для Windows он не входит, и SplitLane работает с любым сервером поддерживаемых протоколов.

## Что он ставит

- **sing-box 1.14.4** — ту же версию, что ядро SplitLane, из [официального выпуска](https://github.com/SagerNet/sing-box/releases/tag/v1.14.4). Скрипт сверяет SHA-256 архива со значениями, записанными в нём самом, и при несовпадении останавливается, ничего не установив.
- **Один сервер, до четырёх входов** (все четыре, если не выбрать другие с помощью `--protocols`):

  | Протокол | Порт | Имя в SplitLane |
  |---|---|---|
  | VLESS + Reality, `xtls-rprx-vision` | 443/tcp | `<address> VLESS` |
  | Hysteria2, самоподписанный сертификат | 443/udp | `<address> Hysteria2` |
  | Shadowsocks 2022, `2022-blake3-aes-128-gcm` | 8388/tcp и udp | `<address> SS2022` |
  | WireGuard | 51820/udp | файл `splitlane-wg.conf` |

  `<address>` — адрес, который стоит в ссылках (из `--host`), поэтому серверы, настроенные скриптом, называются в SplitLane по-разному.

  Там, где провайдеры фильтруют трафик с помощью DPI (Россия, Иран, Китай), обычно проходят VLESS + Reality и Hysteria2; см. [Если что-то не работает](#если-что-то-не-работает).

  Это порты по умолчанию. Если какой-то уже занят другой программой (например, вашим собственным VPN-сервером на 443), выберите другой с помощью `--vless-port`, `--hy2-port`, `--ss-port` или `--wg-port` или поручите `--auto-ports` взять первый свободный из короткого списка (см. параметры).

  Соединения клиентов к адресам loopback и частных сетей (к `127.0.0.1` самого VPS, во внутреннюю сеть провайдера) отклоняются. Службы на публичном адресе VPS остаются доступны через туннель — так же, как из интернета.
- Службу systemd `splitlane-kit`: она работает под собственным системным пользователем, а не под root, и перезапускается после сбоя. sing-box набора лежит в `/usr/local/lib/splitlane-kit/`, вне `PATH`, поэтому уже установленный у вас sing-box и сервер, который он запускает, остаются как были.
- С `--subscription` — [Caddy](https://caddyserver.com), который раздаёт ссылки как подписку по адресу `https://<имя>:8443/<случайный токен>/sub` с сертификатом Let's Encrypt.
- С `--harden` — fail2ban для SSH и автоматические обновления безопасности (см. [Лёгкая защита](#лёгкая-защита---harden)).

## Что нужно

- VPS с Debian 12 и новее или Ubuntu 22.04 и новее, x86_64 или arm64 (aarch64), с systemd; вы входите как root или как пользователь с sudo.
- Публичный адрес IPv4. Скрипт узнаёт его у `api.ipify.org`; с `--host` вы задаёте адрес или имя сами.
- Свободные порты 443/tcp, 443/udp, 8388/tcp, 8388/udp и 51820/udp (только те, что нужны выбранным входам) или те, что вы выберете вместо них. Скрипт сначала проверяет их и, если какой-то занят, останавливается, ничего не установив. Если у провайдера есть межсетевой экран в панели управления, откройте их там.
- Для `--subscription`: Caddy в пакетах дистрибутива (Debian 12 и новее, Ubuntu 24.04 и новее; в Ubuntu 22.04 его нет, и шаг пропускается с сообщением), порты 80/tcp и 8443/tcp (или порт из `--sub-port`), доступные из интернета (Let's Encrypt проверяет порт 80; если его слушает не Caddy, а другая программа, подписка пропускается с предупреждением), и имя, которое указывает на VPS. По умолчанию это `<a-b-c-d>.sslip.io` для адреса a.b.c.d: [sslip.io](https://sslip.io) разрешает такие имена в адрес из самого имени, поэтому свой домен не нужен.

## Установка

На VPS:

```sh
curl -fsSLO https://raw.githubusercontent.com/splitlane-app/splitlane/main/scripts/server/install-singbox-server.sh
less install-singbox-server.sh    # прочитайте то, что запустите от имени root
sudo bash install-singbox-server.sh --subscription    # или без --subscription
```

Если адрес не открывается (например, пока набора нет в ветке `main`), скопируйте файл из своей копии репозитория в домашнюю папку своего пользователя на VPS и запустите его оттуда (в Windows 10 и 11 `scp` встроен):

```sh
scp scripts/server/install-singbox-server.sh <пользователь>@<адрес VPS>:    # на компьютере
sudo bash ~/install-singbox-server.sh --subscription                        # на VPS
```

| Параметр | Что делает |
|---|---|
| `--protocols <список>` | Входы через запятую из `vless`, `hy2`, `ss`, `wg`, например `vless,hy2`. По умолчанию — все четыре. Вход, которого нет в списке, при этом запуске уходит из сервера, ссылок и `.conf`. |
| `--default-protocols <список>` | Входы новой установки. Сервер, который этот набор уже ставил, сохраняет свои: запомненные или все четыре, если их никогда не выбирали. |
| `--subscription` | Также раздавать ссылки как подписку по HTTPS (Caddy, порт 8443; порт 80 — для сертификата). |
| `--harden` | Также поставить fail2ban для SSH и автоматические обновления безопасности (см. [Лёгкая защита](#лёгкая-защита---harden)). |
| `--domain <имя>` | Имя в адресе подписки и в сертификате Hysteria2. По умолчанию — адрес в виде имени sslip.io, например `192-0-2-10.sslip.io`. |
| `--host <адрес или имя>` | Адрес сервера в ссылках и в `.conf`. По умолчанию — публичный адрес IPv4. |
| `--reality-sni <имя>` | Сайт, чьё рукопожатие TLS 1.3 заимствует Reality. По умолчанию — `www.microsoft.com`. |
| `--vless-port <порт>` | Порт VLESS + Reality, tcp. По умолчанию — 443. |
| `--hy2-port <порт>` | Порт Hysteria2, udp. По умолчанию — 443. |
| `--ss-port <порт>` | Порт Shadowsocks 2022, tcp и udp. По умолчанию — 8388. |
| `--wg-port <порт>` | Порт WireGuard, udp. По умолчанию — 51820. |
| `--sub-port <порт>` | Порт подписки, tcp. По умолчанию — 8443. Caddy занимает его и по udp (HTTP/3), поэтому там его не может занять ни один вход. Порт 80 для сертификата нужен в любом случае. |
| `--auto-ports` | Для каждого порта, который не задан параметром и не запомнен прежним запуском, — первый из короткого списка, который не слушает другая программа, вместо порта по умолчанию. Списки: VLESS — 443, 2053, 2083, 2087, 2096 (tcp); Hysteria2 — 443, 4443, 8443, 10443 (udp); Shadowsocks — 8388, 8389, 9388 (tcp и udp); WireGuard — 51820, 51821, 51822 (udp); подписка — 8443, 9443, 7443 (tcp, а также udp для HTTP/3 у Caddy). Если заняты все порты списка, скрипт останавливается. Порт 80 для сертификата не переносится. |
| `--reset` | Новые ключи, ссылки и адрес подписки; прежние перестают работать. |
| `--uninstall` | Удалить набор (см. ниже). |
| `--json` | Вывод для программ: на stdout по одному объекту JSON в строке (шаги, затем итог со ссылками или ошибка с кодом), текст для людей — на stderr. Если программа, запустившая набор, пропала (её SSH-соединение закрыто), запуск всё равно доходит до конца. |
| `--dry-run <папка>` | Проверка: записать всё в папку и проверить конфиг командой `sing-box check`; без systemd, межсетевого экрана, Caddy и apt. Адрес — `192.0.2.10`, если не задан `--host`. |
| `-h`, `--help` | Список параметров. |

`--host`, `--domain`, `--reality-sni`, входы (из `--protocols` или, при новой установке, из `--default-protocols`), порты (в том числе выбранные `--auto-ports`) и `--subscription` запоминаются для следующих запусков, в том числе с `--reset`, до `--uninstall`; тот же параметр с другим значением заменяет прежнее. Уровень журнала — переменная в начале скрипта.

**«Свой VPS» в SplitLane** запускает этот скрипт по SSH с `--json --default-protocols vless,hy2 --auto-ports --harden --subscription` (и с `--host <адрес>`, если введённый там адрес — публичный IPv4): новый сервер получает VLESS + Reality и Hysteria2 на свободных портах, fail2ban, автоматические обновления безопасности и подписку для телефона. На сервере, где набор уже работает, его входы и порты остаются прежними.

## Что он выводит

Ссылки, текст файла WireGuard и, с `--subscription`, адрес подписки. Например, со всеми четырьмя входами (секреты здесь вырезаны):

```text
vless://…@192.0.2.10:443?encryption=none&flow=xtls-rprx-vision&security=reality&sni=www.microsoft.com&fp=chrome&pbk=…&sid=…&type=tcp&headerType=none#192.0.2.10%20VLESS
hysteria2://…@192.0.2.10:443?sni=192-0-2-10.sslip.io&insecure=1#192.0.2.10%20Hysteria2
ss://2022-blake3-aes-128-gcm:…@192.0.2.10:8388#192.0.2.10%20SS2022
https://192-0-2-10.sslip.io:8443/…/sub
```

То же сохраняется в `/root/splitlane-kit/`, который открыт только root: `links.txt` (ссылки), `splitlane-wg.conf` (WireGuard) и `subscription.txt` (ссылки в base64 — в формате подписок).

Если включён ufw, скрипт открывает порты в нём до запуска сервера и Caddy; иначе перечисляет порты, которые нужно открыть в межсетевом экране провайдера.

## Как добавить сервер в SplitLane

- **Ссылки:** на экране «Подключите VPN» (или позже на «Подключение») выберите «Ключ или подписка», вставьте одну ссылку или все, по одной в строке, и нажмите «Добавить».
- **WireGuard:** вставьте текст, который вывел скрипт (или `sudo cat /root/splitlane-kit/splitlane-wg.conf`), от `[Interface]` до последней строки, в «Ключ или подписка», отдельно или вместе со ссылками. Чтобы выбрать сам файл в «Файл настроек», скопируйте его в домашнюю папку на VPS командой `sudo install -m 600 -o "$USER" /root/splitlane-kit/splitlane-wg.conf ~/`, а затем на компьютер: `scp <пользователь>@<адрес VPS>:splitlane-wg.conf .`; когда SplitLane его добавит, удалите обе копии.
- **Подписка:** вставьте адрес подписки в «Ключ или подписка». «Обновить» рядом с подпиской на экране «Подключение» скачивает её заново после запуска, который сохраняет адрес, например с новым `--reality-sni` (новый `--host` сохраняет его только вместе с `--domain`: имя по умолчанию строится из адреса). После `--reset` адрес меняется — см. ниже.

Затем выберите сервер в списке и включите деление.

## Повторный запуск, начать заново, удалить

- **Повторный запуск** сохраняет ключи и ссылки (они лежат в `/etc/splitlane-kit/`). Запустите скрипт снова, чтобы вывести их, изменить параметр или обновить набор. Новый порт меняет ссылки (а `--wg-port` — и `.conf`): добавьте новые в SplitLane и удалите прежние или нажмите «Обновить» рядом с подпиской. Новый список `--protocols` так же добавляет или убирает входы. Запуски идут по одному: запуск, начатый, пока другой ещё работает, ждёт его (до 15 минут).
- **`--reset`** создаёт новые ключи, ссылки и адрес подписки. Прежние перестают работать, а прежний адрес подписки отвечает «не найдено», поэтому «Обновить» изменений не получит. В SplitLane по порядку: выключите деление (пока оно включено, выбранный сервер и его подписку удалить нельзя), удалите на экране «Подключение» прежние подписку и серверы, затем добавьте новый адрес подписки (или новые ссылки и `.conf`). Так в списке никогда не окажутся сразу две подписки с одним именем и похожими серверами.
- **`--uninstall`** останавливает и удаляет службу `splitlane-kit` и её системного пользователя, sing-box набора (`/usr/local/lib/splitlane-kit/sing-box`), `/etc/splitlane-kit` и сайт подписки в Caddy (сам Caddy остаётся). fail2ban с тюрьмой набора и автоматические обновления от `--harden` тоже остаются. Папку `/root/splitlane-kit` он оставляет, чтобы вы удалили её сами (`rm -rf /root/splitlane-kit`), и не трогает добавленные правила ufw (помечены `splitlane-kit`; их видно в `ufw status numbered`).

## Лёгкая защита (`--harden`)

- **fail2ban охраняет SSH.** Набор ставит fail2ban и добавляет тюрьму `sshd` в `/etc/fail2ban/jail.d/splitlane-kit.local`, которая читает журнал systemd (в Debian 12 нет `auth.log`) и блокирует на портах, которые слушает sshd (`port` в тюрьме, например `22` или `2222`). С настройками fail2ban по умолчанию 5 неудачных попыток входа с одного адреса за 10 минут блокируют этот адрес на 10 минут. Если так вышло с вами, подождите или выполните с другого адреса `sudo fail2ban-client unban <адрес>`; `sudo fail2ban-client status sshd` показывает заблокированные адреса. Адреса, подключённые по SSH во время работы набора (ваш или SplitLane), от блокировки освобождены (`ignoreip` в тюрьме; каждый запуск с `--harden` записывает адреса своего времени).
- **Обновления безопасности ставятся сами.** Набор ставит `unattended-upgrades` и включает его ежедневный запуск в `/etc/apt/apt.conf.d/20auto-upgrades`, если этого файла ещё нет; если есть — оставляет как есть.
- Настройки SSH (вход по паролю, порт) не меняются. Неудача здесь — предупреждение, а не ошибка: VPN-сервер работает и без защиты. Повторный запуск ничего не дублирует. `--uninstall` всё это оставляет: fail2ban, его тюрьму от набора и автоматические обновления.

## Безопасность

- **Ключи** создаёт на VPS сам sing-box. Они хранятся в `/etc/splitlane-kit` и `/root/splitlane-kit` (только root) и, когда вы их добавите, в `%ProgramData%\SplitLane\servers.json` на вашем компьютере (только администраторы). Тот, у кого есть ссылка или `.conf`, может пользоваться вашим сервером: обращайтесь с ними как с паролями.
- **Адрес подписки — секрет.** Его защищает только случайный токен в пути: у кого есть адрес, тот получает все ссылки. `--reset` его меняет. На VPS токен записан в файлах, которые могут читать только root и Caddy (`/etc/caddy/splitlane-kit.caddy` и раздаваемая копия, `640 root:caddy`), но виден и через интерфейс управления Caddy на `localhost:2019`, который может спросить любая местная учётная запись. Поэтому тайна подписки держится, только если на VPS нет учётных записей, которым вы не доверяете.
- **Reality заимствует рукопожатие публичного сайта** (по умолчанию `www.microsoft.com`): для всех, у кого нет ключа, порт 443/tcp вашего VPS отвечает как этот сайт, а сервер для таких рукопожатий обращается к сайту. С `--reality-sni` можно выбрать другой сайт с TLS 1.3.
- **У Hysteria2 самоподписанный сертификат, и его ссылка не проверяет сертификат** (`insecure=1`). Трафик зашифрован, но тот, кто может перехватить соединение и ответить вместо вашего сервера, сможет выдать себя за него и узнать пароль Hysteria2. Где это важно, пользуйтесь VLESS + Reality или WireGuard.
- **Служба работает под пользователем `splitlane-kit`** только с двумя привилегиями: занимать порты ниже 1024 (например, 443) и управлять сетью для параметров сокетов ядра sing-box. Конфиг доступен для чтения только root; при запуске службы systemd копирует его в `/run/splitlane-kit` (в памяти).
- **Журнал:** `journalctl -u splitlane-kit`. Уровень — `warn`, соединения в журнал не попадают; `LOG_LEVEL=info` в начале скрипта записывает каждое соединение.

## Если что-то не работает

- `systemctl status splitlane-kit` и `journalctl -u splitlane-kit -n 50` показывают, почему сервер остановился.
- Адрес подписки не открывается: Caddy, возможно, ещё получает сертификат, или порт 80 недоступен из интернета; см. `journalctl -u caddy -n 50`.
- Соединения нет совсем: проверьте, что порты открыты в межсетевом экране провайдера.
- Не работают только Shadowsocks или WireGuard (SplitLane пишет, что не удалось убедиться, что туннель работает, и выключает деление), а VLESS + Reality или Hysteria2 к тому же серверу работают: скорее всего, этот протокол блокирует ваш интернет-провайдер. Некоторые провайдеры (в России, Иране, Китае) распознают Shadowsocks и WireGuard с помощью DPI и обрывают их: в собственной проверке SplitLane в России оба обрывались после первых пакетов, а VLESS + Reality и Hysteria2 проходили. Там пользуйтесь этими двумя.

## Сквозная проверка (для разработчиков)

`e2e/` проверяет «Свой VPS» в SplitLane на настоящих серверах в контейнерах: Debian 12 и 13, Ubuntu 22.04, 24.04 и 26.04 с systemd и sshd (`e2e/Dockerfile`). Запускайте её только локально, в Windows с Docker Desktop (контейнеры Linux), Go и клиентом OpenSSH из Windows (`ssh-keygen`), и не во время проверок сети ПК:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\server\e2e\run-e2e.ps1
```

`-Images debian:12,ubuntu:24.04` выбирает системы, `-NoSmoke` пропускает запуск собранного помощника, `-SmokeOnly` делает только его (на `-SmokeImage`), `-Keep` оставляет контейнеры, чтобы заглянуть внутрь. Перед каждой системой сценарий проверяет, что у ПК свободно не меньше `-MinFreeMB` (2048) МБ памяти, и иначе останавливается: виртуальная машина Docker Desktop растёт на несколько ГБ за систему, так что на ПК, где памяти мало, запускайте по одной системе и перезапускайте Docker Desktop между ними. Для каждой системы сценарий поднимает свежие контейнеры (sshd только на `127.0.0.1`) и запускает `helper/internal/serversetup/e2e_test.go` (`go test -tags e2e`), который настраивает серверы по SSH, как SplitLane:

- root с паролем; повторный запуск даёт те же ссылки; проверяются служба, состояние и тюрьма fail2ban, а неверный пароль, введённый из другого контейнера, тюрьма засчитывает (`fail2ban-client status sshd`);
- пользователь с sudo и паролем; тот же пользователь с ключом (`no_admin`: sudo требует пароль);
- 443/tcp и 443/udp уже заняты (`nc`): VLESS + Reality на 2053, Hysteria2 на 4443;
- сервер, где набор уже запускали без новых флагов: все четыре входа остаются, а `PROTOCOLS` в состоянии не появляется.

Затем он собирает `splitlane-helper.exe` во временную папку и один раз запускает `server-setup` с запросом на stdin, как окно. В конце удаляет контейнеры, сеть и свои образы; последняя строка — `E2E-OK` или `E2E-FAILED`.

Внутри контейнеров `api.ipify.org` отвечает публичным адресом вашего ПК (или VPN, через который он выходит в интернет), и ссылки и имя подписки несут этот адрес. Поэтому каждый контейнер отправляет имена ACME API Let's Encrypt на `127.0.0.1` (сертификат никогда не запрашивается), а Go-тест только делает вид, что скачивает подписку; единственный запуск помощника обращается к адресу подписки по-настоящему 90 секунд и заканчивается `sub_unreachable`. Сам набор скачивает sing-box с GitHub и пакеты дистрибутива, как на настоящем VPS. Пароли придумываются при каждом запуске, ключ тестового пользователя создаётся во временной папке.
