# SplitLane, этап 2, часть 1: установщик

Дата: 2026-11-15. Статус: решения приняты исполнителем по поручению владельца продукта («далее делай как считаешь лучше»); на просмотр владельцу.

Основа — спецификация этапа 1 (`docs/superpowers/specs/2026-11-13-splitlane-stage1-design.md`, далее «спецификация 1»). Здесь — только то, что меняется.

## 1. Зачем и что входит

Этап 2 — публичный бесплатный выпуск (раздел 14 спецификации 1). Владелец продукта выбрал открытый выпуск для всех желающих без затрат. Порядок частей этапа 2:

1. **Установщик** (этот документ): установка и удаление как у обычной программы Windows, перезапуск служебного процесса при сбое, проверка вызывающей программы, сборка на GitHub Actions, единая версия.
2. Обновления: окно узнаёт о новой версии на GitHub Releases и предлагает её поставить.
3. Английский интерфейс.
4. Открытый бета-выпуск: проверка истории git на личные данные, открытие репозитория, страница выпуска с инструкцией про SmartScreen, политика подписи и конфиденциальности, пакет winget.
5. Заявка в SignPath Foundation на бесплатную подпись, когда у проекта появится репутация (условие фонда: проект уже выпущен в подписываемом виде и имеет проверяемую репутацию).

Решения владельца продукта, на которые опирается часть 1:

- Открытый выпуск без денег: первые выпуски не подписаны; подпись — через SignPath Foundation после первого выпуска.
- Служебный процесс остаётся задачей планировщика (не службой Windows) и получает перезапуск при сбое (раздел 4). Служба откладывается до поддержки нескольких пользователей: она работает не в сеансе пользователя (проверенный путь уведомления о завершении сеанса пришлось бы заменить), и не проверено, принимает ли системный Tailscale команды от SYSTEM.

Не входит в часть 1: обновления, английский интерфейс, публикация, подпись, служба Windows, несколько пользователей.

## 2. Размещение

| Путь | Содержимое |
|---|---|
| `%ProgramFiles%\SplitLane\` | окно: `SplitLane.exe` и файлы Electron, `Uninstall SplitLane.exe` |
| `%ProgramFiles%\SplitLane\helper\` | служебный процесс и ядро: `splitlane-helper.exe`, `sing-box.exe`, `libcronet.dll`, `sing-box-LICENSE`, `LICENSE`, `THIRD-PARTY.md` |
| `%ProgramData%\SplitLane\` | без изменений (4.2 спецификации 1) |
| `%AppData%\SplitLane\` | без изменений: настройки окна, кэш значков |

Каталог установки фиксирован (`/D=` и прежнее значение `InstallLocation` не действуют): защита служебного процесса и проверка вызывающей программы (раздел 5) держатся на том, что в `%ProgramFiles%` пишут только администраторы. Папка программы служебного процесса (`place.ProgramDir`) теперь `%ProgramFiles%\SplitLane\helper`; режим продукта, как и раньше, отказывается работать из другого места. Встроенное правило, которое закрепляет трафик самого служебного процесса за дорожкой VPN (6.2 спецификации 1), строится из этого пути.

## 3. Установщик

- **Технология**: NSIS через electron-builder (цель `nsis`), установка для всех пользователей (`perMachine`: установщик сразу просит права администратора, один запрос UAC). Не однокликовый: мастер «Далее → Установить → Готово»; каталог не выбирается (раздел 2). Язык мастера — русский (английский — часть 3).
- **Состав пакета**: окно (как сборка плана 2) и шесть файлов `dist\helper\` в `helper\` (`extraFiles`, не `resources`). У `SplitLane.exe` и установщика — значок SplitLane (знак дорожек из значка в области уведомлений) и сведения о версии с названием SplitLane: так программа называется в диспетчере задач и в «Приложениях».
- **Пользователь установки** — тот, кто вошёл в сеанс, где запущен установщик. Служебный процесс определяет его сам (`--session-user`: имя пользователя текущего сеанса, `WTSQuerySessionInformation`, и его SID; у сеанса без пользователя — сеанс 0 служб, где работает и сборка на GitHub Actions, — пользователь самого процесса); окно для ремонта, как и раньше, передаёт свой SID (`--user-sid`). Если UAC пройден под другой учётной записью (пользователь повышенного процесса не совпадает с пользователем сеанса), установка отказывает до любых изменений, как `install` на этапе 1 (раздел 13 спецификации 1).
- **Порядок установки**:
  1. Проверка запущенного окна: если `SplitLane.exe` работает, мастер просит закрыть его и при согласии завершает (штатная проверка electron-builder).
  2. Подготовка, до любого изменения файлов — в том числе до деинсталлятора прежней версии, который electron-builder запускает при обновлении: `splitlane-helper.exe prepare --session-user` новой версии, извлечённый во временную папку установщика, проверяет пользователя (как выше) и останавливает работающий служебный процесс прежней версии штатно — `helper.shutdown` с возвратом exit node (5.4 спецификации 1), а без ответа канала — возврат по журналу и остановка оставшегося ядра (шаг 3 `install` этапа 1; ядро ищется по образу и в `helper\`, и в корне папки, где оно лежало на этапе 1). Затем `prepare` ждёт до 10 секунд, пока не завершатся все процессы `splitlane-helper.exe` и `sing-box.exe` из папки программы (надзиратель, рабочая копия, служебный процесс этапа 1, ядро), иначе отказывает: занятые файлы нельзя заменить. Если за время ожидания надзиратель запустил новую рабочую копию (пауза перед перезапуском), она тоже получает `helper.shutdown`; ожидание тогда может продлиться дольше 10 секунд (до 20). Пока возврат не подтверждён, установка не продолжается: мастер показывает причину и команду ручного восстановления; ничего не изменено; окно, которое мастер закрыл, запускается снова от пользователя сеанса. Обновление не меняет деление: `helper.shutdown` записывает в `state.json` «было выключено», поэтому `prepare` читает `state.json` до остановки (только из каталога данных, прошедшего проверку) и, если деление было включено, после остановки и ожидания записывает «было включено» обратно — новая рабочая копия включает деление при старте, как после аварийного завершения (5.7 спецификации 1).
  3. Перенос старой раскладки этапа 1: файлы служебного процесса, лежавшие прямо в `%ProgramFiles%\SplitLane\` (установка плана 1B: шесть имён раздела 2), удаляются. Другие файлы этой папки не трогаются.
  4. Копирование файлов. При обновлении с версии этапа 2 перед ним работает деинсталлятор прежней версии в режиме обновления: он удаляет только файлы, задачу и данные не трогает (шаг удаления служебного процесса пропускается).
  5. Настройка на месте: `helper\splitlane-helper.exe install --session-user` — каталог данных со списком доступа, `setup.json`, задача «SplitLane Helper» (XML 4.3 спецификации 1 без изменений, команда — `%ProgramFiles%\SplitLane\helper\splitlane-helper.exe`; перезапуск при сбое — раздел 4). Команда больше не копирует файлы и работает только из `%ProgramFiles%\SplitLane\helper\` (наоборот, чем на этапе 1); остальные проверки `install` (SHA-256 ядра, каталог данных, остановка прежнего служебного процесса) — как на этапе 1.
  6. Ярлыки в меню «Пуск» и на рабочем столе; на последней странице галочка «Запустить SplitLane» (включена) — запуск окна без прав администратора, от пользователя сеанса.
- **Удаление** (Приложения и возможности, или `Uninstall SplitLane.exe`): закрыть окно; `helper\splitlane-helper.exe uninstall` — до удаления файлов: выключение деления с подтверждённым возвратом exit node, ожидание завершения процессов, как у `prepare` (кроме самого `uninstall`), удаление задачи; по галочке «Удалить настройки и вход в Tailscale» (по умолчанию выключена) — ещё `--purge`: каталог данных и `%AppData%\SplitLane\` пользователя, запустившего удаление, удаляются, с сообщением, что устройство `<имя ПК>-splitlane` остаётся в сети Tailscale. Затем деинсталлятор удаляет файлы программы. Отказ `uninstall` (возврат не подтверждён) останавливает удаление с причиной; файлы остаются; закрытое окно запускается снова. `uninstall` больше не удаляет файлы программы (это дело деинсталлятора) и работает из `%ProgramFiles%\SplitLane\helper\`. `%AppData%\SplitLane\` удаляется, только если пользователь повышенного процесса — пользователь сеанса: при UAC, пройденном другой учётной записью, эта папка остаётся (каталог данных удаляется). Если `helper\splitlane-helper.exe` не запускается (файла нет, его заблокировал антивирус), удаление не застревает: мастер спрашивает, удалить ли SplitLane без проверки exit node; тихое удаление продолжается, только если не работают процессы `splitlane-helper.exe` и `sing-box.exe`; задача удаляется через `schtasks`, каталог данных остаётся (его можно удалить вручную). Удаление убирает и значение автозапуска окна `SplitLane` в `HKCU\...\Run`, и копию установщика, которую шаблон electron-builder кладёт в `%LocalAppData%\splitlane-app-updater\` (её убирает и сам установщик в конце установки).
- **Тихий режим** (`/S`, для winget): окно не запускается; тихое удаление данные не удаляет, а с параметром `/PURGE` — удаляет; отказ подготовки, настройки или `uninstall` — ненулевой код выхода.
- **Повторная установка той же версии** — как обновление (шаги 1–6).
- Экран «Первая настройка» в окне остаётся как ремонт: он появляется, только если задачи нет; кнопка запускает `helper\splitlane-helper.exe install --user-sid <SID>` на месте с UAC (как на этапе 1, но без копирования). Окно, не установленное в `%ProgramFiles%\SplitLane\` (папка сборки `win-unpacked` — только для разработки), на этом экране говорит, что SplitLane нужно установить установщиком.
- **Автозапуск окна**: окно при старте уже переписывает свою запись автозапуска на путь своего exe (план 2), поэтому после установки поверх сборки `win-unpacked` запись указывает на установленный `SplitLane.exe`. Значение называется `SplitLane` (явно, а не по AppUserModelID). AppUserModelID окна — `app.splitlane.window`, `appId` сборки, который получают ярлыки: закреплённый ярлык и работающее окно — одна кнопка панели задач.

## 4. Перезапуск при сбое

Окно, как и раньше, само запускает задачу при потере канала (раздел 10 спецификации 1). Перезапуск при сбое нужен на случай, когда окна нет: деление включено, окно закрыто из меню значка, служебный процесс упал — без перезапуска программы дорожки VPN остались бы без защиты до следующего запуска окна.

Настройка задачи `RestartOnFailure` для этого не годится. Проверено 2026-11-15 на ПК владельца (задача пользователя без повышения, запуск по требованию, `RestartOnFailure` раз в минуту до 3 раз): программа, завершившаяся с кодом 3, за 200 секунд не была запущена снова; планировщик перезапускает задачу, только если она не смогла запуститься. Поэтому:

- В режиме продукта процесс, который запускает задача, — **надзиратель**: он проверяет своё место (как сейчас), запускает рабочую копию — тот же `splitlane-helper.exe` с внутренним флагом `--worker` — и ждёт её. Объекта задания с завершением по закрытию нет: при завершении сеанса рабочая копия должна успеть вернуть exit node сама (проверенный путь плана 1A), когда бы система ни завершила надзирателя; рабочая копия, пережившая надзирателя, работает дальше, а новый надзиратель с ней не спорит (канал занят — код 3). Канал, ядро, журнал и всё остальное — в рабочей копии, как сейчас; у надзирателя нет канала.
- Код выхода рабочей копии 0 (штатный выход: `helper.shutdown`, выход без окна через 60 секунд, завершение сеанса), 3 (канал занят: работает другой служебный процесс), 4 (ядро не прошло проверку), 6 (продукт не установлен), 7 — надзиратель выходит с тем же кодом. Любой другой код (паника Go — 2, внутренняя ошибка — 5, аварийное завершение — коды NTSTATUS, принудительное завершение) — сбой: через 5 секунд надзиратель запускает рабочую копию снова; не больше 3 перезапусков за 10 минут, потом он выходит с кодом последнего сбоя. Каждый сбой и перезапуск — строка в `helper.log` (надзиратель пишет в журнал только пока рабочей копии нет).
- Запущенная снова рабочая копия делает обычный старт 5.7 спецификации 1: возврат по журналу, затем повторное включение, если деление было включено.
- В режиме разработки (`--dev`) надзирателя нет: сторож живых проверок сам управляет служебным процессом.

## 5. Проверка вызывающей программы

В режиме продукта служебный процесс принимает в канале только:

- окно `%ProgramFiles%\SplitLane\SplitLane.exe`: при подключении он узнаёт процесс клиента (`GetNamedPipeClientProcessId`), путь его образа (`QueryFullProcessImageNameW`) и сравнивает его целиком, без учёта регистра, с путём окна. Другие программы папки (ядро, `resources\elevate.exe`, деинсталлятор) не допускаются: обычный пользователь может запустить их с любыми аргументами;
- процессы с повышенными правами (маркер доступа клиента повышен, `TokenElevation`): такой процесс и так сильнее канала — он может остановить задачу и заменить файлы программы. Это нужно `prepare` из временной папки установщика и сторожу живых проверок.

Чужой клиент отключается до первого сообщения, с записью в журнал без пути пользователя (только имя файла образа). Ошибка определения процесса или пути — отказ. Список доступа канала (5.1 спецификации 1) остаётся. В режиме разработки (`--dev`) проверки нет: `slctl` и сценарная проверка работают как раньше.

Чтобы установленное окно нельзя было просто запустить как Node.js со своим кодом, у сборки выключаются предохранители Electron (fuses): `RunAsNode`, `EnableNodeOptionsEnvironmentVariable`, `EnableNodeCliInspectArguments`; включается `OnlyLoadAppFromAsar`. Проверка целостности `app.asar` не нужна: файл лежит в папке, куда пишут только администраторы. Собранное окно, запущенное с ключами отладки (`--remote-debugging-port`, `--remote-debugging-pipe`, `--remote-allow-origins`, `--inspect`, `--inspect-brk`, `--inspect-port`, `--js-flags`), сразу завершается — до окна и до канала.

Остаточный риск раздела 11 спецификации 1 сужается, но не закрывается: другая программа того же пользователя больше не может просто подключиться к каналу, но может внедрить код в работающее окно (оно работает без повышенных прав, от того же пользователя). От вредоносной программы, уже работающей от имени пользователя, SplitLane не защищает. Проверка по подписи — после подписи (часть 5).

## 6. Версия и сборка

- **Одна версия** продукта — `version` в `app/package.json` (начиная с `0.2.0`). Служебный процесс получает её при сборке (`-X main.version`), отвечает ею в `hello`; окно показывает её на экране «Подключение». Имя установщика — `SplitLane-Setup-<версия>.exe`.
- **Сборка на GitHub Actions** (`windows-latest`): получение ядра со сверкой SHA-256 (`scripts\fetch-core.ps1`), Go и Node с закреплёнными версиями (Go 1.27.4, Node 24, pnpm 12.9.1), `go vet`, `go test`, `pnpm typecheck`, `pnpm test`, сборка служебного процесса, окна и установщика, проверка установщика (раздел 7), артефакты: установщик и его SHA-256. На метке `v<версия>` (совпадает с `version`, иначе сборка падает) — черновик выпуска GitHub с этими файлами. Подписи нет (часть 5 добавит шаг SignPath).
- Локально — `scripts\build-installer.ps1` (те же шаги, без выпуска).

## 7. Проверка

- **Модульные тесты служебного процесса**: надзиратель (решение «перезапустить или выйти» по коду и истории сбоев — чистая функция; запуск, перезапуск и выход на подменной рабочей копии), `install` на месте (отказ вне `helper\`, без копирования), `--session-user` (пользователь сеанса и отказ при другом пользователе повышенного процесса — на подменах), `prepare` (остановка прежнего служебного процесса и отказ при неподтверждённом возврате — на подменах), `uninstall` из `helper\` без удаления файлов программы, проверка вызывающей программы (чистая функция решения по пути образа и повышению; ошибка определения — отказ; в режиме разработки — без проверки), путь встроенного правила в конфиге ядра (эталонные конфиги).
- **Модульные тесты окна**: путь служебного процесса для ремонта, сообщение неустановленного окна и отображение версии.
- **Проверка установщика на GitHub Actions** (бегун — администратор, без Tailscale): тихая установка, проверка файлов, задачи (команда) и списка доступа каталога данных, предохранители Electron установленного `SplitLane.exe`, повторная установка с `/D=` в другую папку (установка остаётся в `%ProgramFiles%\SplitLane\`), отсутствие копии установщика в `%LocalAppData%\splitlane-app-updater\`, тихое удаление с `/PURGE` и без него (значение автозапуска `SplitLane` удаляется), проверка, что задачи и файлов нет. Служебный процесс там не запускается и сеть не трогает.
- **Живая проверка на ПК владельца** (под сторожем плана 1A): установка поверх установки этапа 1 (перенос раскладки), запуск окна, включение и выключение, сбой рабочей копии при закрытом окне — перезапуск надзирателем и повторное включение, удаление без удаления данных и повторная установка, удаление с удалением данных и вход заново. Чистая виртуальная машина — в части 4.

## 8. Известные ограничения части 1

- Установщик и программы не подписаны: SmartScreen предупреждает при запуске скачанного установщика (до части 5); через winget предупреждения нет.
- Один пользователь Windows, как на этапе 1.
- Установка только в `%ProgramFiles%\SplitLane\`.
- Отказ тихого удаления (`/S`) не виден по коду выхода: деинсталлятор NSIS перезапускает свою копию из `%TEMP%`, а исходный процесс сразу выходит с кодом 0. Отказ виден по оставшимся файлам, задаче и записи в «Приложениях»; в обычном режиме мастер показывает причину. Проверка установщика на GitHub Actions ловит его по коду копии.
- Стандартная проверка electron-builder «программа запущена» заменена своей: она завершала бы все процессы из папки установки, в том числе служебный процесс и ядро, до штатной остановки с возвратом exit node. Установщик и деинсталлятор закрывают только окно `SplitLane.exe`.
- Если UAC при удалении пройден под другой учётной записью, удаляется запись автозапуска окна этой учётной записи, а запись пользователя сеанса остаётся (она указывает на удалённый exe и ничего не запускает); папку `%AppData%\SplitLane\` пользователя сеанса `--purge` в этом случае тоже не трогает.
- Тихое удаление, запущенное без прав администратора, после отказа не запускает окно снова (деинсталлятор закрывает окно до перезапуска себя с повышением). winget запускает удаление для всех пользователей с повышением, там окно запускается.
- Если пользователя сеанса не удалось определить, `uninstall --purge` не удаляет `%AppData%\SplitLane\`.
- Подпись (часть 5): electron-builder подписывает и файлы `extraFiles`, а `install` сверяет SHA-256 неизменённого `sing-box.exe`; при подписи ядро исключается (`win.signExts: ["!sing-box.exe"]`).
