# SplitLane, этап 2, часть 2: обновления

Дата: 2026-11-15. Статус: проект согласован с владельцем продукта в разговоре («делай как лучше»); спецификация написана исполнителем.

Основа — спецификация части 1 (`docs/superpowers/specs/2026-11-15-splitlane-stage2-installer-design.md`, далее «спецификация установщика») и спецификация этапа 1 (`docs/superpowers/specs/2026-11-13-splitlane-stage1-design.md`, «спецификация 1»). Здесь — только то, что меняется.

## 1. Зачем и что входит

Пользователь открытой беты (часть 4) не должен сам следить за выпусками: окно узнаёт о новой версии на GitHub Releases, по одному нажатию скачивает её, проверяет и ставит; деление после обновления остаётся, как было (`prepare` сохраняет признак «было включено», спецификация установщика, раздел 3).

Выбран собственный небольшой механизм, а не electron-updater и не только winget: новых зависимостей нет; шаги, тексты и запуск установщика — наши и стыкуются с установщиком части 1; без подписи electron-updater проверял бы то же самое (хеш из того же выпуска); загрузка разницы между версиями не нужна для беты.

Не входит: загрузка разницы между версиями, предварительные выпуски и каналы, понижение версии, проверка подписи (часть 5 — после подписи), обновление без участия пользователя.

## 2. Источник

- Выпуски — GitHub Releases репозитория `splitlane-app/splitlane`. Окно запрашивает `GET https://api.github.com/repos/splitlane-app/splitlane/releases/latest` без входа: это последний опубликованный выпуск, не черновик и не предварительный. Предел GitHub без входа — 60 запросов в час с адреса; окно делает их единицы в сутки.
- Выпуск подходит, если его метка — `v<версия>` (`<версия>` — три числа `x.y.z`), версия больше версии окна, и среди файлов выпуска есть ровно `SplitLane-Setup-<версия>.exe` и `SplitLane-Setup-<версия>.exe.sha256`, оба с адресом `https://github.com/splitlane-app/splitlane/releases/download/v<версия>/<имя>`. Иначе выпуск пропускается (в журнал окна — почему), а пользователь видит «установлена последняя версия», если версия не больше, или «не удалось проверить обновления», если выпуск испорчен.
- Сеть — `net.fetch` Electron из основного процесса (системный прокси учитывается). Только `https`; переадресации проверяются по одной: разрешены узлы `api.github.com`, `github.com`, `objects.githubusercontent.com`, `release-assets.githubusercontent.com`. Предел ответа API — 1 МБ, файла `.sha256` — 1 КБ, установщика — 400 МБ; без данных 60 секунд — обрыв.
- Окно до сих пор не обращалось к сети, кроме канала служебного процесса (план 2). Теперь оно обращается к GitHub — это попадёт в политику конфиденциальности (часть 4): какие адреса, когда и что передаётся (обычный запрос без данных пользователя; GitHub видит адрес и версию окна в заголовке `User-Agent: SplitLane/<версия>`).

**Источник для проверок.** Переменная окружения `SPLITLANE_UPDATE_FEED`, только вида `http://127.0.0.1:<порт>`, заменяет `https://api.github.com` и адреса файлов: тогда API — `<источник>/repos/splitlane-app/splitlane/releases/latest`, файлы — только с того же источника. Другое значение переменной — источник по умолчанию и строка в журнале окна. Нужна, пока репозиторий закрыт (GitHub без входа не отдаёт его выпуски), и для автоматических тестов.

## 3. Когда окно проверяет

- Через 30 секунд после старта окна и затем раз в 24 часа, пока окно работает; по пункту «Проверить обновления» в меню значка и кнопке на экране «Подключение» — сразу.
- Настройка «Проверять обновления» (в настройках окна рядом с «Запускать при входе», включена по умолчанию) выключает автоматические проверки; ручная работает всегда.
- Проверок нет у окна, которое не может ставить (`canInstall` части 1 — `false`: собранное окно вне `%ProgramFiles%\SplitLane\`), и в разработке без `SPLITLANE_UPDATE_FEED`.
- Одновременно идёт одна проверка или одна загрузка.

## 4. Что видит пользователь

Плашка обновления — отдельная от плашек состояния деления, над доской; на экране «Подключение» — строка состояния обновлений рядом со строкой версий.

| Состояние | Плашка | Действия |
|---|---|---|
| доступна версия X | «Доступна версия X» | «Обновить», «Что нового» (страница выпуска в браузере), «Позже» (скрыть до следующей проверки) |
| загрузка | «Загрузка версии X: N%» | «Отменить» |
| проверка файла | «Проверка версии X…» | — |
| запуск установщика | «Установка версии X: Windows попросит подтверждение» | — |
| UAC отменён | «Обновление отменено» | «Обновить» |
| ошибка загрузки или проверки | «Не удалось скачать версию X: <причина>» | «Повторить» |
| после обновления | «SplitLane обновлён до X» (один раз) | закрыть |
| установщик отказал | «Обновление до X не установлено: <причина>» | «Повторить», «Что нового» |

Ручная проверка без нового выпуска — «Установлена последняя версия» на экране «Подключение»; ошибка проверки — «Не удалось проверить обновления: <причина>». Автоматическая проверка без нового выпуска и её ошибки плашек не показывают (строка в журнале окна). «Что нового» открывает только `https://github.com/splitlane-app/splitlane/releases/tag/v<версия>`.

## 5. Загрузка и проверка

- Папка загрузки — `%TEMP%\SplitLane-update\`; перед загрузкой из неё удаляется всё прежнее. Файл пишется под временным именем и переименовывается после проверки.
- SHA-256 считается во время загрузки и сверяется с файлом `.sha256` выпуска (строка `<64 шестнадцатеричных знака>  SplitLane-Setup-<версия>.exe`, как его пишет сборка части 1). Несовпадение, обрыв, превышение размера — ошибка, файл удаляется, установщик не запускается.
- Это проверка целостности, не подлинности: оба файла из одного выпуска GitHub. Подлинность даст подпись (часть 5): окно будет сверять подпись установщика перед запуском.

## 6. Установка

- Окно записывает в свои настройки «начато обновление до X» и запускает установщик с UAC: `SplitLane-Setup-X.exe /S --force-run` (через `Start-Process -Verb RunAs`, как ремонт служебного процесса в плане 2). Отмена UAC — плашка «Обновление отменено», запись снимается.
- Дальше всё делает установщик части 1 в тихом режиме: закрывает окно, `prepare` останавливает служебный процесс с подтверждённым возвратом exit node и сохраняет признак «было включено», установка, `install` на месте; `--force-run` запускает окно новой версии от пользователя сеанса. При отказе `prepare` или `install` установщик, как и сейчас, запускает окно снова (старой версии, если файлы не заменены).
- **Итог установки.** Установщик пишет файл `%ProgramData%\SplitLane\export\last-install.txt` (пишут только администраторы, пользователь читает; спецификация 1, 4.2): три строки — версия установщика, `ok` или `refused`, причина (одна строка, пустая для `ok`). Пишет при успехе (после `install`) и при отказе `prepare` или `install`, в обычном и в тихом режиме. Файл заменяется целиком.
- Окно при старте, если в настройках записано «начато обновление до X»: версия окна — X → «SplitLane обновлён до X»; иначе `last-install.txt` с версией X и `refused` → «Обновление до X не установлено: <причина>»; иначе — «Обновление до X не установлено» без причины. Запись снимается.

## 7. Изменения по частям

- **Окно** — модуль обновлений в основном процессе: проверка, загрузка, сверка, запуск; чистые функции разбора выпуска, сравнения версий, разбора `.sha256` и `last-install.txt`, переходов состояния обновления — без `electron`. Мост: состояние обновления в снимке, команды «проверить», «обновить», «отменить», «позже», «что нового». Плашка, строка на экране «Подключение», пункт меню значка, настройка.
- **Установщик** (`app/build/installer.nsh`) — запись `last-install.txt`.
- **Служебный процесс** — без изменений.
- **Сборка** — версия для проверочных сборок задаётся параметром `scripts\build-installer.ps1 -Version <x.y.z>` (по умолчанию — `version` из `app/package.json`; служебный процесс и окно получают одну версию).
- **Проверка установщика на GitHub Actions** — после каждой установки и при отказе: `last-install.txt` с версией и `ok`.

## 8. Проверка

- **Модульные тесты окна**: сравнение версий; разбор выпуска (подходящий, без файлов, лишние или чужие адреса, черновик, предварительный, не больше текущей, испорченная метка); разбор `.sha256` и `last-install.txt`; переходы состояния; проверка переадресаций по узлам; загрузка со сверкой, превышением размера, обрывом и отменой — на локальном HTTP-сервере в тесте на `127.0.0.1`; источник для проверок (принимается только `http://127.0.0.1:<порт>`); итог после перезапуска для трёх случаев; плашка и строка на экране «Подключение» для каждого состояния.
- **Проверка установщика на GitHub Actions**: файл итога после установки.
- **Живая проверка на ПК владельца** (под сторожем): поставить сборку A (версия 0.2.90) установщиком; локальный источник (`SPLITLANE_UPDATE_FEED`) отдаёт сборку B (0.2.91); при включённом делении «Обновить» → UAC → окно B на доске, деление снова включено, «SplitLane обновлён до 0.2.91»; повтор с отменой UAC — «Обновление отменено», версия A на месте. Версии 0.2.90 и 0.2.91 — только для проверки; первый открытый выпуск (часть 4) получит версию больше них.

## 9. Известные ограничения части 2

- Пока репозиторий закрыт, обновления не находятся (GitHub без входа не отдаёт выпуски); они заработают с открытием репозитория (часть 4).
- Подлинность установщика не проверяется до подписи (часть 5): человек, получивший доступ к выпускам репозитория, может выложить свой установщик с верным хешем.
- Скачанный установщик лежит во временной папке пользователя между проверкой и запуском; программа того же пользователя может его подменить — тот же класс угроз, от которого SplitLane не защищает (спецификация установщика, раздел 5). UAC всё равно покажет запрос.
- Загрузка целиком (~160 МБ), без разницы между версиями.
