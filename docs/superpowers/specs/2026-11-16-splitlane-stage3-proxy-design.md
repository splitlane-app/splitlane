# SplitLane, этап 3, часть 1: ключи, подписки и WireGuard

Дата: 2026-11-16. Статус: решения приняты исполнителем по поручению владельца продукта («все решения за тобой, делай как лучше»).

Основа — спецификация этапа 1 (`docs/superpowers/specs/2026-11-13-splitlane-stage1-design.md`, «спецификация 1») и спецификации этапа 2. Здесь — только то, что меняется.

## 1. Зачем и что входит

До сих пор SplitLane работал только с Tailscale и exit node. Большинство людей, которым нужно разделение по программам, пользуются ключами и подписками (VLESS с Reality, Shadowsocks/Outline, Trojan, Hysteria2 и другими) или файлами WireGuard. Ядро SplitLane — sing-box 1.14.4 — умеет эти протоколы само, второе ядро не нужно.

Входит:
- **Протоколы**: VLESS (в том числе Reality и `xtls-rprx-vision`), VMess, Trojan, Shadowsocks (в том числе Shadowsocks 2022), Hysteria2, TUIC v5 — по ссылкам; WireGuard — по файлу `.conf`.
- **Транспорты** этих протоколов: без транспорта (TCP), WebSocket, gRPC, HTTPUpgrade, HTTP/2, QUIC; TLS с SNI, ALPN, отпечатком uTLS, Reality.
- **Источники**: вставка текста (одна или несколько ссылок по строке; адрес подписки `https://…`; текст файла WireGuard), выбор файла `.conf`, подписка по адресу (список ссылок, в том числе в base64).
- **Выбор сервера** — один выбранный сервер ведёт дорожку VPN; переключение — как смена exit node сейчас.
- Tailscale остаётся способом подключения наравне с новым; пользователь выбирает один из них.

Не входит (позже): AmneziaWG (нет в sing-box) и OpenVPN (`openvpn-client` в ядре есть — отдельная часть), форматы подписок Clash/sing-box JSON, транспорты `xhttp`/`splithttp`/`kcp`, заголовок `http` для TCP, плагины Shadowsocks (SIP003), автоматический выбор сервера и проверка задержки, обновление подписок по расписанию, несколько выбранных серверов.

## 2. Словарь

- **Способ подключения** (connector): `tailscale` или `proxy` («ключ, подписка или файл»).
- **Сервер** — один импортированный сервер: имя, протокол, адрес, параметры, источник (вставлен вручную, файл или подписка).
- **Подписка** — адрес, по которому получается список серверов; её серверы обновляются вместе.

## 3. Хранение и безопасность

- Серверы и подписки — в `%ProgramData%\SplitLane\servers.json` (список доступа папки данных: только SYSTEM и администраторы, спецификация 1, 4.2), запись атомарная. Хранится исходный текст каждого сервера (ссылка или текст `.conf`) и его id; при каждой сборке конфига ядра текст разбирается заново — разборщик один источник истины. Подписка хранит адрес (в нём часто токен — это секрет), имя, время обновления и ошибку последнего обновления.
- В `state.json` — только несекретное: способ подключения и id выбранного сервера. Архив диагностики не включает `servers.json`; в журналах и в текстах ошибок ядра (`config_invalid`) UUID, пароли, ключи и адреса подписок маскируются.
- **Окно не передаёт путей.** Файл `.conf` выбирает основной процесс окна в диалоге, читает его сам (не больше 64 КБ, UTF-8) и отправляет служебному процессу текст. Служебный процесс принимает только текст ссылок, текст `.conf` или адрес подписки и сам разбирает их в типизированную модель; сырой JSON sing-box/Clash не принимается; полей, которые называют файлы (`*_path`, `certificate_path`), интерфейсы (`bind_interface`) или другие выходы (`detour`), модель не имеет.
- **Загрузка подписки** — делает служебный процесс: только `https`; запрещены адреса loopback, link-local, частные сети и сеть Tailscale (`100.64.0.0/10`) — и после каждой переадресации (не больше 5); предел ответа 1 МБ, времени 20 секунд; заголовок `User-Agent: SplitLane/<версия>`. Пока деление включено, запрос идёт через дорожку VPN (правило служебного процесса 6.2 спецификации 1).
- Разборщики строгие: неизвестное или неподдерживаемое (транспорт, тип шифрования, параметр AmneziaWG, плагин) — отказ с причиной, а не молчаливое отбрасывание. Каждая отклонённая строка возвращается окну с причиной.

## 4. Протокол канала (версия 2)

Версия протокола становится 2 (окно и служебный процесс ставятся вместе; несовпадение уже обрабатывается экраном «Обновите»).

- **Состояние**: новое поле `connector`: `"tailscale" | "proxy"`; новый блок `proxy`: `servers: [{id, name, protocol, source}]` (только несекретное; `source` — `manual`, `file` или id подписки), `selected: id | null`, `subscriptions: [{id, name, updatedAt, count, error}]` (`name` — имя узла из адреса, без пути и токена; `updatedAt` — время последнего удачного обновления; `error` — код последней неудачи или `null`). Блок `tailscale` остаётся.
- **Методы**:
  - `proxy.add {text, name?}` — ссылки (по строке), текст `.conf` или адрес подписки; `name` — имя файла `.conf` без папки (окно передаёт его, когда прочитало текст из файла; путь — `bad_request`). Ответ `{added: [id], existing: n, rejected: [{line, code}], rejectedMore: n}`: `added` — только серверы, новые для списка; `existing` — сколько серверов текста уже были в списке (повторно не добавлены); `rejected` — первые 50 отклонённых строк (номер строки и код причины, без самой строки), `rejectedMore` — сколько ещё. Строка 0 — весь текст: `too_long`, `too_many` (добавление превысило бы предел — не добавляется ничего), неудача загрузки подписки (`fetch_*`), подписка без серверов (`empty_subscription` или код её первой отклонённой строки). Тот же адрес подписки ещё раз — обновление этой подписки.
  - Первый добавленный сервер становится выбранным, если выбранного нет. Способ подключения при этом становится `proxy`, только если Tailscale не готов (вход не выполнен или exit node не выбран) и деление выключено (`off` или `error`); иначе сервер выбран на будущее, способ остаётся `tailscale`, и пользователь переключается, выбрав сервер (`proxy.select`).
  - `proxy.refresh {id}` — обновить подписку: её серверы заменяются новыми (выбранный сохраняется, если сервер с тем же id остался, иначе выбор снимается); ответ — как у `proxy.add`. Неудача — ошибка с кодом: `unknown_server`, `too_many`, `fetch_*`, `empty_subscription` или код разбора первой отклонённой строки (например `unsupported_protocol`); серверы подписки остаются прежними, код сохраняется в её `error`.
  - `proxy.remove {id}` — сервер или подписка (со всеми её серверами); выбор снимается, если выбранного сервера больше нет.
  - `proxy.select {id}` — выбрать сервер и сделать способ подключения `proxy`; при включённом делении — переподключение, как смена exit node сейчас; при переходе на `proxy` в `off` или `error` режим настройки Tailscale останавливается (`tailscale.login` запускает его снова).
  - `tailscale.setExitNode` делает способ подключения `tailscale`.
  - Ограничения при включённом делении действуют только при способе `proxy`: выбранный сервер, подписку, из которой он, и обновление этой подписки нельзя (`wrong_phase`; в `starting` и `stopping` — `busy`). При способе `tailscale` серверы и подписки меняются в любой фазе.
  - Загрузка подписки (`proxy.add` с адресом, `proxy.refresh`) идёт параллельно с другими запросами того же соединения: `proxy.add`, `proxy.refresh` и `diagnostics.export` отвечаются отдельно, ответы сопоставляются по id, и клиент, которому нужен их результат, ждёт ответа. Загрузка одна за раз (вторая — `busy`); уход клиента или закрытие канала прерывает её, ничего не меняя.
  - Новые коды ошибок: `unknown_server` (нет сервера или подписки с таким id), `too_many`, `empty_subscription`; у `proxy.refresh` также `fetch_*` и коды разбора.
  - Пределы: текст `proxy.add` — 64 КБ; серверов — 500; подписок — 20.
- **Причины**: новая `no_server` — способ `proxy`, но сервер не выбран или не разбирается. `not_logged_in`, `no_exit_node`, `login_expired` относятся только к способу `tailscale`.

## 5. Ядро и дорожки

- Дорожка VPN (`vpn`) — выход ядра выбранного сервера: VLESS, VMess, Trojan, Shadowsocks, Hysteria2, TUIC — выходы (`outbounds`); WireGuard — конечная точка (`endpoints`, в sing-box 1.11+ WireGuard — только так). Конечная точка Tailscale и служба API Tailscale в конфиге способа `proxy` не создаются.
- Всё остальное — без изменений: проверки дорожек (ipify через `vpn` и `direct`), зашифрованный DNS 1.1.1.1 через `vpn`, правила 6.2, `clash_mode` для «всё напрямую», трафик системного Tailscale напрямую, частные и местные адреса напрямую.
- Правило 0 (отклонять соединения, которые открывает сам узел) остаётся для WireGuard, если проверка на ПК покажет, что конечная точка WireGuard открывает соединения так же, как Tailscale; иначе — только для Tailscale.
- Системный Tailscale: если в приложении выбран exit node, он мешает любому способу (весь трафик ушёл бы через него), поэтому согласование 5.6–5.7 спецификации 1 (выключение на время деления и возврат по журналу) остаётся для обоих способов.
- Сбой сервера (неверный пароль, сервер недоступен) выглядит как `tunnel_not_proven` при включении и как `vpn_unreachable` во время работы — как недоступный exit node сейчас; тексты этих причин и плашек становятся нейтральными («VPN-сервер» вместо «exit node»).
- Ничего специфичного для Tailscale (режим настройки, вход, путь `direct`/`relay` и его перезапуск, истечение входа) для способа `proxy` не работает.

## 6. Окно

- **«Подключите VPN»**: плитки «Ключ или подписка» и «Файл настроек» становятся рабочими:
  - «Ключ или подписка» — поле для вставки (ссылки по строке или адрес подписки) и кнопка «Добавить»; ниже — итог: сколько добавлено, какие строки отклонены и почему (номер строки и причина, без секрета).
  - «Файл настроек» — выбор файла WireGuard `.conf` в диалоге (фильтр `.conf`), затем то же.
  - После добавления — список серверов (как список exit node: группа переключателей; имя, протокол, источник) и шаг «Включить».
- **«Подключение»**: раздел зависит от способа: для Tailscale — как сейчас; для ключей — список серверов с выбором, «Добавить» (то же поле), «Обновить» у каждой подписки (с временем последнего обновления и ошибкой, если была), «Удалить» у сервера и у подписки; переход между способами — выбор сервера или exit node.
- **Шапка**: плашка «<имя сервера> · <протокол>» для способа `proxy`.
- **Тексты**: причины `no_server`, коды отказов разбора (`unsupported_protocol`, `unsupported_transport`, `bad_link`, `missing_field`, `bad_wireguard`, `amneziawg`, `plugin`, `too_many`, …), нейтральные тексты причин и плашек, уведомления — на двух языках; глоссарий: «сервер» — "server", «ключ» — "key", «подписка» — "subscription", «Ключ или подписка» — "Key or subscription", «Файл настроек» — "Configuration file".
- Дорожка «Через VPN»: «Сайты видят адрес сервера <имя>» — для обоих способов.

## 7. Проверка

- **Модульные тесты**: разборщики каждого протокола и транспорта на образцах реальных ссылок разных клиентов (v2rayN, Shadowrocket, Outline, NekoBox, Hiddify, 3x-ui), включая отказы; fuzz-тесты разборщиков; конфиг ядра для каждого протокола — эталоны (`*.golden.json`) и проверка настоящим ядром (`sing-box check`, переменная `SPLITLANE_CORE`); загрузка подписки на локальном сервере в тесте (base64 и простой список, переадресации, запрет частных адресов, пределы); хранение и маскировка; методы протокола и переходы способа; окно — плитки, список, выбор, удаление, обновление подписки, плашка, тексты.
- **CI** — без изменений, плюс `sing-box check` всех эталонов (ядро уже скачивается).
- **Живая проверка** (под сторожем; нужен VPS владельца): на VPS ставится сервер sing-box (готовый скрипт и конфиг из `scripts/` для владельца: VLESS+Reality, Hysteria2, Shadowsocks 2022, WireGuard), SplitLane получает ссылки и `.conf`; для каждого протокола — включение, проверка дорожек, смена сервера, выключение с возвратом exit node; подписка — по адресу на том же VPS.

## 8. Известные ограничения части 1

- Протоколы и транспорты — только перечисленные в разделе 1; AmneziaWG и OpenVPN — позже.
- Подписки обновляются по кнопке, не по расписанию.
- Сервер без UDP не пропустит UDP-трафик программ дорожки VPN (игры, звонки).
- Нет проверки задержки и автоматического выбора сервера.
