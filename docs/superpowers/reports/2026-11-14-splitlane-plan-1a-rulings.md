## Припаркованные находки финальной проверки — для плана 1B

Это настоящие дефекты, найденные финальной проверкой кода и отложенные решением исполнителя. Два из них помечены MUST: их нужно исправить до того, как план 1B включит запуск по триггеру при входе и режим «всё напрямую» в окне.

- disable during the stopping half of the 5.7 start-up or the setExitNode reconnect is dropped (matches the literal 5.1 table; the window offers no action in stopping) — real, deferred to Plan 1B — cost if wrong: a disable pressed in a few-second window is ignored and routing comes back on.
- LoadJournal/load() treat a transient I/O error on an intact restore.json as "no journal" (findings 2 and 5) — real, not exercised by live task 23 (fresh dev data, slguard restores independently); MUST be fixed before Plan 1B ships the logon-trigger start — cost if wrong: after a crash plus a read error the PC can be left with neither core nor system exit node until the next start.
- save() only logs a failed state.json write; lanes.set reports success — real, deferred to Plan 1B (surface write errors as apply_failed) — cost if wrong: after a restart an old layout or WasOn comes back.
- LoadState treats a read error like corruption and the first save overwrites state.json — real, deferred to Plan 1B (retry and keep the file on I/O error) — cost if wrong: layout and selected exit node lost after a rare disk error.
- pipe Server.Serve returns on any Accept error and main discards it — real, deferred to Plan 1B (log and restart accept loop) — cost if wrong: helper stops accepting new clients after a rare CreateNamedPipe failure.
- routing.allDirect and lanes.set are not operations, so the crash watcher does not wait for them (same class as the fixed clear race; re-review out-of-scope) — real, not exercised by task 23 — MUST be fixed before Plan 1B's window uses all-direct — cost if wrong: a crash during an all-direct switch can end with a stale mode.
