# SplitLane 0.5.2 (beta)

[English](#english) · [Русский](#русский)

## English

SplitLane 0.5.2 fixes split routing that refused to turn on while the Tailscale app used an exit node with its default DNS setting. Install it over 0.5.1, or let SplitLane update itself; split routing and your servers stay as they were.

### What changed

- **Split routing turns on with the default DNS setting of the Tailscale app.** With **Use Tailscale DNS settings** on (the default), the Tailscale app keeps a DNS rule for all names while it uses an exit node. SplitLane took that rule for a tailnet that overrides DNS and refused to turn split routing on, with "Tailscale overrides DNS for all names…", although SplitLane turns that exit node off itself and the rule goes with it. The same check ran for **Turn on split routing at startup** and when SplitLane restarted split routing itself (after a network change, when you change the exit node or the server), so those failed the same way. SplitLane now turns the exit node off first and checks then. Only a rule that stays means a tailnet that overrides DNS for all names: in that case the exit node is turned back on and you see the same message as before.
- The service's Go libraries are updated (`golang.org/x/crypto` 0.59.0, `golang.org/x/sys` 0.50.0).

Only PCs where the Tailscale app is installed, manages DNS and uses an exit node were affected.

With the Tailscale app managing DNS, MagicDNS names still don't resolve while split routing is on; your devices stay reachable by their Tailscale addresses. This limitation is not new.

### Install and update

Download `SplitLane-Setup-0.5.2.exe` and `SplitLane-Setup-0.5.2.exe.sha256` below and verify the download as described in the [0.3.0 notes](https://github.com/splitlane-app/splitlane/blob/main/docs/release-notes/0.3.0.md), or use **Check for updates**. The other known limitations are the same as in 0.5.1; the full list is in the [README](https://github.com/splitlane-app/splitlane#readme).

## Русский

SplitLane 0.5.2 исправляет отказ включить деление, когда приложение Tailscale использует exit node при своей настройке DNS по умолчанию. Ставьте поверх 0.5.1 или обновитесь из самого SplitLane; деление и ваши серверы остаются, как были.

### Что изменилось

- **Деление включается при настройке DNS приложения Tailscale по умолчанию.** Когда в приложении Tailscale включено «Use Tailscale DNS settings» (так по умолчанию), оно держит правило DNS для всех имён, пока использует exit node. SplitLane принимал это правило за сеть Tailscale, которая переопределяет DNS, и отказывался включать деление с сообщением «Tailscale подменяет DNS для всех имён…», хотя сам выключает этот exit node, и правило уходит вместе с ним. Та же проверка выполнялась для настройки «Включать деление при запуске» и когда SplitLane перезапускал деление сам (после смены сети, при смене exit node или сервера), поэтому они не срабатывали так же. Теперь SplitLane сначала выключает exit node и только потом проверяет. Лишь правило, которое осталось, означает сеть, переопределяющую DNS для всех имён: тогда exit node возвращается, а вы видите прежнее сообщение.
- Обновлены библиотеки Go службы (`golang.org/x/crypto` 0.59.0, `golang.org/x/sys` 0.50.0).

Ошибка касалась только компьютеров, где приложение Tailscale установлено, управляет DNS и использует exit node.

Когда приложение Tailscale управляет DNS, имена MagicDNS по-прежнему не разрешаются, пока деление включено; устройства остаются доступны по адресам Tailscale. Это ограничение не новое.
